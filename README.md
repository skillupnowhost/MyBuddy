# MyBuddy

Your private, self-hosted AI companion. Open-source, no paid inference API required.

This is **Phase 1** of a multi-phase build: real local LLM inference, streaming chat, auth, and conversation history. See [Roadmap](#roadmap) for what comes next (RAG, memory, fine-tuning, custom models).

## Architecture

```
Frontend (Next.js)
      │
      ▼
Backend (FastAPI) ──── PostgreSQL (users, conversations, messages)
      │
      ▼
LLMProvider abstraction
      │
      ▼
OllamaProvider ──→ Ollama (real local inference)
```

The backend never calls Ollama's HTTP API directly from routes — everything goes through `app/services/llm_provider.py`'s `LLMProvider` interface (`backend/app/services/llm_provider.py`). Swapping in vLLM, llama.cpp, or a future MyBuddy-trained model means adding one new implementation class; nothing else changes.

## Requirements

- **Python** 3.11+
- **Node.js** 20+
- **PostgreSQL** 16 (native install for local dev; Docker for deployment)
- **Ollama** (native install — [ollama.com/download](https://ollama.com/download))
- **Docker + Docker Compose** — only needed for the production-style deployment path, not required for local dev

### Hardware note

Model choice depends on your machine. Run this to check what you're working with:

- **RAM < 8GB, no dedicated GPU** → `llama3.2:1b` or `qwen2.5:1.5b-instruct` (this repo's default)
- **8–16GB RAM, no GPU** → `llama3.2:3b` or `qwen2.5:3b-instruct`
- **NVIDIA GPU with 8GB+ VRAM** → `llama3.2:8b`, `mistral:7b`, or larger, and consider vLLM for higher throughput (future provider)

Set your choice via the `OLLAMA_MODEL` environment variable — nothing is hard-coded.

## Local development (native — recommended for low-RAM machines)

Running Postgres and Ollama natively avoids Docker Desktop's VM overhead, which matters a lot on machines with limited RAM.

### 1. Install and start Ollama

```powershell
winget install Ollama.Ollama
ollama pull llama3.2:1b
```

Ollama runs as a background service on `localhost:11434` once installed.

### 2. Install PostgreSQL natively

Install PostgreSQL 16 (via installer from postgresql.org, or `winget install PostgreSQL.PostgreSQL`). Create the database:

```sql
CREATE USER mybuddy WITH PASSWORD 'change_me';
CREATE DATABASE mybuddy OWNER mybuddy;
```

### 3. Configure environment

```bash
cp .env.example .env
# Edit DATABASE_URL if your local Postgres isn't on the default host/port
```

### 4. Backend

```bash
cd backend
python -m venv .venv
.venv\Scripts\activate      # Windows
pip install -r requirements.txt
alembic upgrade head
uvicorn app.main:app --reload --port 8000
```

Visit `http://localhost:8000/docs` for interactive API docs (auto-generated by FastAPI), and `http://localhost:8000/health` / `/ready` for health checks.

### 5. Frontend

```bash
cd frontend
npm install
npm run dev
```

Visit `http://localhost:3000`.

### 6. Run tests

```bash
cd backend
pytest -v
```

Tests use SQLite in-memory and a `MockProvider` (`app/services/mock_provider.py`) instead of a real Ollama connection — they verify auth, persistence, and streaming plumbing without needing the model server running.

## Deployment (Docker Compose)

For a production-style deployment on a server with more RAM (or a GPU):

```bash
cp .env.example .env   # fill in real secrets
docker compose up --build
```

Add `-f docker-compose.yml -f docker-compose.gpu.yml` if the host has an NVIDIA GPU.

## OpenAI-compatible API

`POST /v1/chat/completions` accepts the standard OpenAI request shape and can be used with existing OpenAI-client tooling by pointing the base URL at your MyBuddy backend and using a MyBuddy JWT access token as the bearer token.

```json
{
  "model": "llama3.2:1b",
  "messages": [{"role": "user", "content": "Hello MyBuddy"}],
  "stream": true
}
```

## Security notes (Phase 1)

- Passwords hashed with bcrypt, never stored plaintext.
- JWT access tokens (short-lived) + refresh tokens; all conversation/chat/model routes require a valid access token.
- CORS restricted to `FRONTEND_ORIGIN`.
- Auth endpoints rate-limited.
- Every conversation/message query is scoped to `user_id` — no cross-user access.
- Secrets live in `.env`, never in code. `.env` is gitignored.

## Roadmap

| Phase | Focus |
|---|---|
| **1 (this)** | Real local LLM, streaming chat, auth, conversation history, OpenAI-compatible API |
| 2 | Document upload, embeddings, Qdrant, RAG |
| 3 | Long-term memory (user preferences, persistent facts) |
| 4 | Fine-tuning (LoRA/QLoRA), model registry |
| 5 | Tools/agents, model evaluation, admin dashboard |
| 6 | Experimental custom-trained MyBuddy model (research track) |

Later phases attach to this codebase without rework: RAG will add `backend/app/rag/` + a vector store service in Compose; memory will add `backend/app/memory/`; fine-tuning lives in a separate `training/` module that never runs inside the API process.
